# Vite 开发模式与生产模式性能差异

## 1. 问题现象

在工作台页面中，前端使用 Vite 开发服务器运行时，页面首次打开较慢。浏览器网络面板可以看到：

- 页面产生了较多静态资源请求；
- ECharts、Markdown、Axios 等模块分别加载；
- 页面总加载时间约为 5 秒以上；
- 会话消息接口的请求参数已经是 `limit=4`，响应体约 6.7KB。

切换到生产构建后的预览模式后，页面明显变快。

这说明问题主要不是数据库分页或消息接口返回过慢，而是开发模式下前端模块处理方式造成的额外开销。

## 2. 开发模式是如何工作的

执行：

```powershell
npm run dev
```

Vite 会启动开发服务器。浏览器访问页面时，不会直接拿到一个完整的打包文件，而是按模块请求源码：

```text
浏览器
    → 请求 App.vue
    → 请求 PowerChart.vue
    → 请求 ECharts 模块
    → 请求 Markdown 模块
    → Vite 实时转换模块
    → 返回浏览器
```

开发模式的主要特点：

1. 按需转换模块；
2. 保留源码结构，便于调试；
3. 开启 HMR 热更新；
4. 保留 Source Map 和开发错误提示；
5. 不进行完整的代码压缩和模块合并；
6. 依赖模块可能产生较多网络请求。

因此，开发模式的目标是“修改代码后快速反馈”，而不是“首次加载速度最优”。

## 3. 生产模式是如何工作的

执行：

```powershell
npm run build
npm run preview -- --host 0.0.0.0 --port 5173
```

构建阶段会使用 Rollup 对前端代码进行处理：

```text
Vue 源码
    → 模块分析
    → Tree Shaking
    → 模块合并
    → JavaScript 压缩
    → CSS 压缩
    → 生成静态资源
```

生产构建完成后，浏览器直接读取已经生成好的文件，不再让 Vite 在请求过程中实时编译源码。

生产模式的主要特点：

- 请求数量更少；
- JavaScript 和 CSS 已压缩；
- 删除没有使用的代码；
- 没有 HMR 开销；
- 没有实时模块转换开销；
- 静态资源更容易被浏览器缓存；
- 更接近真实部署环境。

## 4. 两种模式的对比

| 对比项 | 开发模式 | 生产模式 |
|---|---|---|
| 启动命令 | `npm run dev` | `npm run build` + `npm run preview` |
| 模块处理 | 浏览器请求时实时转换 | 构建阶段一次性处理 |
| 请求数量 | 较多 | 较少 |
| 代码状态 | 保留源码结构 | 已合并、压缩 |
| HMR | 开启 | 不存在 |
| Source Map | 完整 | 通常关闭或精简 |
| 首屏速度 | 可能较慢 | 通常更快 |
| 适用场景 | 日常开发调试 | 发布、验收、性能测试 |

## 5. 本项目中的实际判断

本项目的后端会话接口已经完成分页：

```http
GET /api/sessions/{session_id}/messages?limit=4
```

真实 MySQL 只读测试结果显示：

- 消息接口直接调用平均耗时约 2.85ms；
- 单条 SQL 查询耗时约 0.3~0.7ms；
- `/sessions` 响应体约 508B；
- `/messages?limit=4` 响应体约 6.7KB；
- 没有发现明显的重复会话请求。

因此，开发模式下页面加载慢的主要原因不是：

- MySQL 查询慢；
- `before_id` 分页失效；
- 前端仍然请求 20 条消息；
- 会话接口返回过大的数据。

更可能的原因是：

```text
Vite 开发服务器
    → 实时编译 Vue 模块
    → 处理 ECharts 等依赖
    → 产生大量开发资源请求
    → 浏览器等待模块加载完成
```

## 6. 为什么生产模式更快

生产模式更快的核心原因是：

```text
开发模式：运行时编译
生产模式：构建时编译
```

开发模式相当于每次打开页面时，Vite 还要参与“准备代码”。

生产模式则是在构建阶段提前完成了这些工作，用户访问时只需要下载静态文件。

可以类比为：

```text
开发模式：边做饭，边给用户上菜
生产模式：提前做好饭，用户到店直接取餐
```

## 7. 推荐的验证流程

### 7.1 开发模式

```powershell
cd frontend
npm run dev
```

用于：

- 编写功能；
- 调试接口；
- 查看 Vue 错误；
- 使用 HMR 快速修改页面。

### 7.2 生产模式

```powershell
cd frontend
npm run build
npm run preview -- --host 0.0.0.0 --port 5173
```

用于：

- 验收页面加载速度；
- 测试静态资源请求数量；
- 观察首屏渲染速度；
- 判断性能问题属于前端构建还是后端接口。

## 8. 后续性能优化方向

如果生产模式仍然较慢，再继续排查：

1. 将 ECharts 改为按页面或组件懒加载；
2. 对大型图表组件进行代码拆分；
3. 检查 `loadSessions()` 和 `selectSession()` 是否重复调用；
4. 使用浏览器 Performance 面板区分网络、脚本执行和渲染耗时；
5. 在 FastAPI 增加请求耗时日志，记录真实 HTTP 接口耗时；
6. 对历史消息、图表快照和会话列表分别进行性能测量。

## 9. 结论

Vite 开发模式慢，并不代表生产系统慢。开发模式优先保证开发效率，生产模式优先保证加载性能。

本项目当前的判断是：

```text
数据库分页已生效
    → 后端接口本身很快
    → 开发模式仍有大量模块转换和请求
    → 生产构建后页面明显变快
    → 当前主要瓶颈属于开发服务器加载链路
```

因此，后续性能验收应以生产构建结果为准，不能只根据 `npm run dev` 的表现判断系统最终性能。
