# SolarAgent 阶段一学习复盘

## 目标

阶段一不是单独修 Bug，而是把技术验证版提升到可继续交付的生产基础：身份可信、数据不丢、人工确认可恢复、异步不阻塞、行为可验证。

## 1. 为什么不能信任前端 user_id

前端传来的 user_id 只是普通请求数据，攻击者可以手工修改。正确做法是：登录后签发服务端签名的 JWT，后端从 Authorization Bearer Token 的 sub 字段读取用户身份。会话所有权校验使用这个服务端解析出的身份。

## 2. JWT 与后续 Vue 前端

后端只暴露标准 Bearer Token 接口，当前内置页面和未来 Vue 3 页面都使用同一套 API。Vue 通过 Axios 拦截器给普通请求加 Authorization，SSE 使用 fetch 手动加同一个请求头，因此不需要为 Vue 重写聊天协议。

## 3. 密码哈希迁移

SHA256 适合完整性校验，不适合密码存储。Argon2id 会使用高成本参数抵抗暴力破解。当前系统只接受 Argon2id，旧 SHA256 用户会被拒绝登录，后续由管理员清理旧账号。

## 4. SSE 与 ask_user

Agent 工具运行在同步线程，SSE 运行在 asyncio 事件循环。Bridge 使用 asyncio.Queue 推送问题，threading.Event 等待回复。用户回复后设置 Event，工具线程恢复执行。问题必须携带真实 question，不能只传固定的“请回复”。

## 5. 为什么 async 函数仍可能阻塞

async def 只表示调用协议是异步的。如果函数内部直接执行同步 LLM 或数据库调用，仍会阻塞事件循环。阶段一使用 asyncio.to_thread 将同步摘要放入线程执行，保证 SSE 和其他请求可以继续处理。

## 6. Schema 与迁移

源码模型、初始化脚本和升级脚本必须保持一致。初始化脚本负责新环境，迁移脚本负责旧环境，测试 Event 不应隐藏在生产初始化脚本中。删除数据的任务必须明确保留周期和备份策略。

## 7. 产品意识

每个技术能力都必须对应真实用户任务：预测不是只返回模型数值，而要支持确认、解释、复盘和错误处理；导入不是只写库，而要先预览、清洗、确认、入库并返回报告。
